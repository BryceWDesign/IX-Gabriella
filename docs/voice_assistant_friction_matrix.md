# Voice Assistant Friction Matrix

This matrix turns common assistant complaints into IX-Gabriella requirements.
It is a product planning artifact, not a claim that these rankings are final.
A later research pass should mine App Store reviews, Google Play reviews,
support forums, Reddit threads, and UX research papers.

| # | Friction theme | IX-Gabriella requirement | v0.1 support |
|---:|---|---|---|
| 1 | Assistant mishears user | Show `I heard` before risky actions | Yes |
| 2 | False wake or false accept | Receipt every important turn | Partial |
| 3 | Wrong device/action | Confirmation for smart-home commands | Yes |
| 4 | No proof of what happened | Tamper-evident receipt chain | Yes |
| 5 | Hard to correct | Correction loop rebuilds the request | Yes |
| 6 | Assistant guesses when unsure | Low confidence requires confirmation | Yes |
| 7 | Talks too much | Verbosity control planned | Contract only |
| 8 | Unwanted attitude | Calm default tone | Documentation |
| 9 | Privacy anxiety | Memory opt-in and ad guardrails | Yes |
| 10 | Hidden data use | Privacy summary and App Store checks | Yes |
| 11 | Ads feel creepy | No voice-content ad targeting | Yes |
| 12 | Broken routines | Routine preview before execution | Planned |
| 13 | Bad smart-home reliability | Fewer actions, stronger checks | Partial |
| 14 | Weak calendar/email safety | Draft-only behavior by default | Yes |
| 15 | Poor accent handling | Acoustic confidence affects policy | Yes |
| 16 | No confidence display | Intent confidence stored in receipts | Yes |
| 17 | No audit trail | JSON receipt export | Yes |
| 18 | Memory feels invasive | Explicit memory approval required | Yes |
| 19 | Feature regressions | Quality gate and manifest | Yes |
| 20 | Too much magic, not enough control | Ask-before-act spine | Yes |
